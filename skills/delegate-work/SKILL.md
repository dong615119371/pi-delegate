# 外包手册

两把工具，同一个能力，区别只在**等不等**：

| 工具 | 等吗 | 用在 |
|---|---|---|
| `opencode` | **等**，同回合拿结果 | 下一步必须用它 |
| `delegate_async` | **不等**，返回作业号 | 有别的事可做 |

`delegate_async` 只在装了 async-jobs 宿主时才出现。看不到就是没有。

## 一、先判断该不该外包

**先确认手上有哪些工具。** 只看得到 `opencode` 就是同步模式，只能等；看得到 `delegate_async` 才有不等这个选项。看不到就不要提它，也不要想它。

**外包的是"做"，不是"想"。** 决定、判断、设计——留在这里。

| 该外包 | 不该外包 |
|---|---|
| 批量把 `var` 改 `const` | 决定用哪种架构 |
| 10 个文件加同样注释 | 判断这段逻辑对不对 |
| 机械重构、改名 | 需要读完整个对话才能决定的事 |
| 统计、巡检、生成样板 | 需要多轮商量的探索 |

**判据**：这件事能不能用一段话讲清、且不需要它问你问题？能 → 外包。不能 → 自己干。

## 二、它看不到你的对话

委派出去的是**另一个模型**，独立的上下文。它只知道你写在 `task` 里的字。

所以每一条 task 必须自带全部前提：

```
❌ "把刚才那个 bug 修了"
✅ "改 C:/proj/src/a.js 第 42 行：函数返回 null 时改成返回空数组。
    只改这一处，不要动其他逻辑。"

❌ "按之前说的做"
✅ "在 C:/proj/src/ 目录下，把所有 .js 文件的 var 改成 const。
    跳过 node_modules。改完不要跑测试。"
```

**所有路径必须绝对。** OpenCode 忽略工作目录，永远在用户家目录跑。相对路径会静默指错地方。

## 三、选模型

只用免费模型，名单实时从 CLI 读。当前常见的：

| 模型 | 特点 | 用在哪 |
|---|---|---|
| `deepseek-v4.1-flash-free` | 能力较强 | 默认、要质量 |
| `glm-5.3-flash-free` | 能力较强 | 同上 |
| `minimax-m3.1-flash-free` | 1M 上下文 | 长任务、大代码库 |
| `longcat-2.5-preview-free` | 1M 上下文 | 同上 |
| `nemotron-3-ultra-free` | 中等 | 一般活 |
| `beam-free` | 速度快 | 简单批量 |

**写错模型名会被拒**，报错里会列出当前可用的。

思考档位加在模型名后面：

```
opencode/minimax-m3.1-flash-free#max
```

档位：`low` / `medium` / `high` / `xhigh` / `max`。不写默认 `high`。

**写不存在的档位会报 `Variant unavailable`**，不会静默降级。

## 四、三种调用形态

**单条**：

```
opencode(task: "……")
```

**并行**（互不相干的任务）：

```
opencode(tasks: [
  { task: "改 C:/a.js" },
  { task: "改 C:/b.js" },
])
```

`delegate_async` 也收 `tasks` 数组，一次丢多个。

**串行链**（只有同步支持）：

```
opencode(chain: [
  { task: "分析 C:/a.js，输出问题清单" },
  { task: "根据这份清单：{previous}，写修复方案" }
])
```

`{previous}` 会被替换成上一步的输出。**异步没有这个能力**——它的任务互相独立。

## 五、拿到作业号之后

**那是这一轮的终点。** 转身做别的。

**三条禁令**：

1. **不要轮询**、不要重跑、不要指望同一回合拿到结果
2. **不要写长文**——结果没到，写的总结没有信息增益，还会把结果往后推
3. **不要汇报"我提交了"**——用户屏幕上看得见。只在**结果回来**时说话

**手上一件事都没有时，直接结束这一轮。** 结果到达时会作为新消息把你叫醒。

## 六、结果不对怎么办

**先读，别急着重试。**

```
job_logs <作业号>          # 看它在干什么、卡在哪
```

常见情况：

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 输出里有 `provider.auth` | 走了代理，IP 被风控 | 关代理直连，见下 |
| 结果空、退出码 0 | task 写得太模糊 | 重写 task，补全路径和意图 |
| 改错了文件 | 没写绝对路径 | 重发，路径写全 |
| `Variant unavailable` | 思考档位写错 | 用 `low`/`medium`/`high`/`xhigh`/`max` |
| `not a free model` | 用了收费 id | 换成报错里列出的免费模型 |

**不要因为一次失败就换个说法重试。** 先看 `job_logs` 里它到底做了什么——它可能已经改了一部分文件。

## 七、不要走代理

OpenCode 按 **IP** 风控免费模型，报错原文：

```
OpenCode's free models aren't available from your current network
because we've detected abusive traffic from this IP address.
This isn't related to your account.
```

"**this IP address**"——和你的用量无关。代理节点共享，同一出口 IP 上别人的流量也记在它头上。

表现：作业 `killed`、退出码 1、输出里 `provider.auth`。切直连立刻恢复。

## 八、多轮审查

免费模型适合跑多轮检查，因为它不花钱。**不要一次要它做完所有事。**

```
第 1 轮：让它只发现问题，不改代码
    opencode(agent: "plan", task: "审 C:/proj/src/*.js，列出每个文件的问题。不要改。")

第 2 轮：拿第 1 轮的清单去改
    opencode(chain: [
      { agent: "plan", task: "……列出问题" },
      { task: "根据这份清单：{previous}，逐个修复" }
    ])

第 3 轮：让它自己验证
    opencode(task: "检查 C:/proj/src/a.js，确认 var 已全部改成 const。只报告，不改。")
```

**为什么要分轮**：一次性让它"发现问题并修复"，它会跳过分析直接改，改错了你看不出来。分开之后每一步都可验证。

`agent: "plan"` 是只读的，不会动文件。

## 九、并发上限

- 同步 `opencode`：一次最多 6 个并行任务（内部限 3 个同时跑）
- 异步 `delegate_async`：受 async-jobs 的全局上限（7 个）约束，和 bash 作业抢槽位

**跑一批 7 个 bash 命令时不要再丢委派任务**——它会被排在队尾。

## 十、决策流程

```
要做的事是什么？
   │
   ├─ 需要判断/商量 → 自己干
   │
   ├─ 机械活，下一步就要结果 → opencode
   │     ├─ 多步有依赖 → chain + {previous}
   │     └─ 单纯跑一次 → task
   │
   └─ 机械活，有别的事可做 → delegate_async
         ├─ 多个独立任务 → tasks 数组
         └─ 拿到作业号 → 转身做别的，结果会自己来
```

**一句话**：能不能用一段话讲清、且不需要它问你？能就外包，不能就自己干。
