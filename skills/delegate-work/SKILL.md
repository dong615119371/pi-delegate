# 外包手册

外包的活必须**可核验**。免费模型最常见的失败不是做错，是**说做完了、其实没做**。

## 一、能不能外包

判据：**能不能写成一段不需要它提问的话？** 能 → 外包，不能 → 自己干。

| 外包 | 不外包 |
|---|---|
| 批量替换、改名、统计、巡检、生成样板 | 架构决定、方案选择 |
| 已知模式的重复改动 | 逻辑正确性判断 |
| 单文件单处修改 | 需要读整个对话才能定的事 |

**它看不到你的对话。** task 里没写的前提，对它不存在。

## 二、task 必含四项

缺任何一项，结果都不可信。

| 项 | 要求 | 缺了会怎样 |
|---|---|---|
| **绝对路径** | 它在家目录跑 | 相对路径静默指错地方 |
| **边界** | 改哪些、**不改哪些** | 顺手改别的，你发现不了 |
| **产出清单** | 见下方模板，缺项视为未完成 | 只能拿到「已完成」三个字 |
| **约束** | 跑不跑测试、动不动格式 | 它自己决定，可能覆盖你的改动 |

### 产出清单模板（直接抄进 task）

```
完成后必须逐项列出，缺一项视为未完成：
  1. 改动文件：完整绝对路径
  2. 每个文件改了什么：行号 + 改前 → 改后
  3. 改动总数：涉及 N 个文件，共 M 处
  4. 未改动的：路径 + 跳过原因
  5. 遗留问题：做不到的、不确定的，逐条列出
```

**第 4 项最关键**——它必须自报跳过了什么。「跳过」没有虚假收益，编不出来；
自报改了什么却很容易编。

完整示例：

```
目标：C:/proj/src/ 下所有 .js 的 var 改成 const
范围：跳过 node_modules、跳过 dist/
产出：完成后逐项列出
  1. 改动文件的完整绝对路径
  2. 每个文件：行号 + 改前 → 改后
  3. 改动总数：涉及 N 个文件，共 M 处
  4. 未改动的文件：路径 + 跳过原因
  5. 遗留问题：做不到或不确定的，逐条列出
约束：不要跑测试，不要改格式，不要动其他文件
```

## 三、验证

**顺序从便宜到贵，前一条不过不进下一条。**

### 1. 抽检（不可省）

它声称改了 8 个文件 → 随机挑 1-2 个自己 grep 一次残留模式。

```
grep -n "var " C:/proj/src/a.js
```

### 2. 核验轮与被核验轮分离

同一轮里让它「做并检查」= 自证，无效。

核验轮必须是**新的一次调用**，且**不给它上一轮的解释**，只给文件路径和规则，问是否符合。它不知道上一轮怎么做的，才可能发现上一轮漏了什么。

### 3. 要可机械核对的产出

```
❌ 改完了吗？
✅ 逐行列出：文件路径 | 剩余 var 数量 | 例外及原因
```

拿到表后自己抽查一两行——编的表和真实的表在抽查时立刻分开。

### 4. 判断类任务跑两份

同一判断任务丢给两个不同模型，比对结论。

- 一致 → 可信度上升
- 不一致 → **task 有歧义**，自己看，不要选一个信

### 禁止的验证方式

**「你确定吗」——它一定回答确定。** 要问可核对的细节，不问态度。

## 四、分轮

**改代码之前先要计划。**

```
第 1 轮  agent: "plan"  → 列出改什么、为什么、风险（只读，不动文件）
        ↑ 自己看这份计划对不对，错了在这一步拦住
第 2 轮  照计划改
第 3 轮  独立核验（见三.2）
```

| 该分轮 | 不该分轮 |
|---|---|
| 「找问题」和「修问题」 | 纯替换 |
| 改完之后的核验 | 统计、列清单 |
| 多文件改动（先计划） | 单文件单处 |

**依赖传递**：后一步需要前一步结论 → `chain` + `{previous}`（**只有同步支持**）。
**不需要 → 并行 `tasks`**，异步任务之间互相独立。

## 五、拿到作业号

**那是这一轮的终点。**

1. **不轮询**、不重跑、不指望同一回合拿到结果
2. **不写长文**——结果没到，总结没有信息增益，还会把结果往后推
3. **不汇报「我提交了」**——屏幕上看得到。只在**结果回来**时说话

手上没别的事 → 直接结束这一轮，结果会作为新消息把你叫醒。

## 六、失败处理

**先读再重试。** 一次失败就换说法重发是最常见的浪费——它可能已经改了一部分文件，重发会叠加破坏。

```
job_logs <作业号>
```

| 症状 | 先查什么 | 不要做什么 |
|---|---|---|
| 输出空、退出码 0 | task 是否太模糊 | 重发同样的 task |
| 改了不该改的文件 | 边界是否写清 | 只补一句「别改别的」 |
| 结果像编的 | 有没有要它交路径和行号 | 问「你确定吗」 |
| 报模型 / 档位错误 | 名字是否拼错 | 猜——报错里会列可用的 |

## 七、模型与并行

- 模型名实时从 CLI 读，写错被拒并列出当前可用的。只接受免费模型。
- 档位写在模型名后：`#low` / `#medium` / `#high` / `#xhigh` / `#max`。判断类任务开高档，机械替换开低档。
- **同步**一次最多 6 个任务（内部同时跑 3 个）。**异步**受 async-jobs 全局上限 7 约束，和 bash 作业抢槽位——**一批 bash 在跑时不要丢委派**，会排队尾。
- 大文件或大代码库优先选大上下文模型。

## 八、决策流程

```
要做的事是什么？
   │
   ├─ 需要判断 / 商量 → 自己干
   │
   ├─ 有依赖的多步 → opencode + chain + {previous}
   │     第 1 步只读出计划，审完再往下
   │
   ├─ 机械活，下一步就要结果 → opencode（单条或 tasks 并行）
   │     结果必须带路径 / 行号 / 数量，否则不信
   │
   └─ 机械活，有别的事可做 → delegate_async
         ├─ 多个独立任务 → tasks 数组
         └─ 拿到作业号 → 转身做别的，结果会自己来
```

**收尾必问**：我抽检了吗？
